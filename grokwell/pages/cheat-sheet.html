Shell Quick Reference

SOC-REF-07 · taped to the SecOps monitor

For the on-call analyst. The usual moves for finding your way around a box, reading what's there, and checking what's running. This is not an exhaustive list — these devices run more than it mentions.

Moving around

pwdwhere am I right now
lslist this directory
ls -lalist all, hidden files too
cd <dir>change directory (cd .. goes up)
whoamiwhich account am I
idmy user/group IDs

Reading things

cat <file>dump a file to screen
less <file>page through a long file
head <file>first 10 lines (add -n 3 for 3)
tail <file>last 10 lines, where logs keep the latest
grep <text> <file>search for a string
historywhat this account typed before
find <dir> -mmin -5files changed in the last 5 minutes
open <url | file.html>to open URLs or html pages on the side panel

What's running

ps auxall running processes
systemctl status <svc>is a service up, and why
systemctl stop <svc>stop a service (needs sudo)
journalctl -u <svc>a service's logs
ss -tlnplistening sockets / ports

Containers

docker psrunning containers
docker logs <name>a container's output
docker stop <name>stop a container
docker inspect <name>how it was started

Across the network

ssh <host>connect to another box
ip athis box's own addresses
~/.ssh/hidden directory with important info (ls -a shows it)
sudo -lwhat am I allowed to run as root

Getting unstuck

helpthe short in-shell command list
cheatsheetpull up this card again
lookre-read where you are
resetfix a garbled terminal, on the box you type it on
If you know the tool but not the flags

Type the tool name on its own — e.g. just docker — and the shell will offer a few candidate invocations to pick from by number. Not every pick is the right one; read before you choose.

And when a command wants elevated rights, reach for sudo. What you're allowed to become is its own small puzzle on a box like this.
